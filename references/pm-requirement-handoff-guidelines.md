# WhatsGPS PM Requirement Handoff Guidelines

本文件用于给产品经理、交互设计、AI/Cursor/Codex 生成页面时使用。它不是完整设计系统，也不替代后续 Figma 组件库；它是当前版本在没有正式设计规范时的需求原型交付规范。

## 1. 文档定位

### 现在这份规范能解决什么

- 产品经理写需求和原型时，有统一的页面结构、组件样式、交互状态要求。
- AI 根据需求生成页面时，不会随意做成营销页、卡片页或和现有系统不一致的样式。
- UI review 时，可以明确指出问题属于字段缺失、状态缺失、流程缺失、组件不一致还是视觉 token 偏移。
- 前端实现时，可以优先沿用 Vue 2 / Element UI 风格，而不是重新创造一套界面。
- 对传感器、报警、续费、转移、指令这类硬件业务，可以要求 PM 补齐必要的业务规则和边界状态。

### 现在这份规范不能替代什么

- 不能替代完整的 Figma 组件库。
- 不能替代所有历史页面的逐页走查。
- 不能替代接口字段文档和设备协议说明。
- 不能替代最终的交互整改方案。
- 不能保证所有老页面已经完全一致；它的目标是先管住新增需求和改版需求。

## 2. 给 PM 的最小交付要求

每个需求原型至少要补齐以下内容，否则不建议进入 UI 或前端开发。

### 2.1 基础信息

- 需求名称。
- 目标页面或入口。
- 涉及页面族：Dashboard、我的客户、设备详情、定位监控、视频、财务、组织、报表、系统配置、个人中心。
- 涉及对象：设备、客户、服务版本、SIM/ICCID、定位、视频、指令、报警、传感器、续费、转移、保养。
- 目标用户：管理员、经销商、监管员、普通成员等。
- 不包含范围：本期不做什么。

### 2.2 页面结构

PM 需要在原型中说明：

- 页面主区域是什么：表格、表单、地图、视频网格、报表图表、设备详情工作台。
- 是否有左侧客户/设备树。
- 是否有顶部筛选区。
- 是否有批量操作区。
- 是否有表格分页、选中数量、导出/下载。
- 是否需要弹窗、抽屉、二级弹窗或设备详情工作台 tab。

### 2.3 字段和数据

设备相关需求必须明确这些字段是否展示、是否可编辑、是否只读：

- 设备名称。
- IMEI。
- SIM 号码。
- ICCID。
- 设备型号。
- 在线/离线/未激活/过期状态。
- 服务版本。
- 平台到期。
- 用户到期。
- 所属客户。
- 最后位置或地址。

如果某个字段不展示，PM 需要说明原因；不能默认省略。

### 2.4 操作和流程

PM 需要写清楚：

- 默认进入状态。
- 查询/筛选条件。
- 新增、编辑、删除、保存、取消的流程。
- 批量操作是否支持跨页。
- 更多菜单里有哪些操作。
- 每个操作成功后页面如何反馈。
- 操作失败、网络失败、设备离线、设备过期、权限不足时如何处理。

### 2.5 状态

每个需求至少要考虑：

- 加载中。
- 空数据。
- 查询无结果。
- 禁用。
- 校验错误。
- 保存成功。
- 保存失败。
- 无权限。
- 设备离线。
- 设备未激活。
- 服务已过期或即将过期。
- 长文本截断和 tooltip。

## 3. 样式和组件硬规则

### 3.1 必须保持的视觉方向

- PC 端 B 端后台，不做营销官网风格。
- 页面背景使用浅蓝灰，主内容为白色面板。
- 主色使用 `#0068FF`。
- 主要文字为深蓝黑，辅助文字为灰蓝。
- 表格、表单、筛选、批量操作优先。
- 页面信息密度可以高，但必须可扫描。

### 3.2 组件使用规则

- 表格：用于设备、客户、记录、日志、续费、报表、配件列表。
- 表单：用于详情编辑、传感器配置、报警阈值、系统配置。
- Tabs：用于同一对象下的任务切换，例如设备详情里的多个 tab。
- Dialog：简单确认或简单表单。
- 大型工作台 Dialog：设备详情和硬件配置，不要做成小弹窗。
- Switch：用于报警开关、监控开关、启用/禁用。
- Radio/Segmented：用于 1年/终生、有线/蓝牙、模式切换。
- Checkbox：用于批量选择、ACC 打火/熄火、多选报警项。
- Unit input：用于速度、时间、电压、油量、温湿度、载重等数值输入。

### 3.3 禁止随意调整的内容

- 不要把设备列表改成卡片墙。
- 不要把设备详情改成普通小弹窗。
- 不要隐藏 IMEI、SIM、ICCID、设备型号、状态、到期、所属客户等核心字段。
- 不要让每个操作按钮都变成蓝色主按钮。
- 不要新增大面积紫色、棕色、米色、重渐变、玻璃拟态、重阴影。
- 不要在后台页面做 hero、大插画、营销文案。
- 不要把硬件配置拆成很多装饰性卡片。
- 不要只给正常状态，不给空、错、禁用、离线、过期状态。

## 4. 页面类型选型

### 4.1 我的客户 / 设备列表类

适用于：我的客户、设备记录、保养记录、分享管理、续费管理。

必须包含：

- 客户或设备上下文。
- 筛选区。
- 批量操作。
- 表格。
- 操作列。
- 分页。
- 空状态。
- 选中数量。

不建议：

- 只放统计卡片，不放表格。
- 把筛选条件散落在页面多个位置。
- 操作列只有“更多”，没有高频操作入口。

### 4.2 设备详情工作台类

适用于：详情、服务版本、所属客户、追踪、指令、续费、转移、报警设置、设备保养、定时任务、自定义提醒、传感器配置。

必须包含：

- 大尺寸工作台结构。
- 顶部 tab。
- 当前设备上下文。
- 主要表单/表格区域。
- 底部 取消/确定 或任务型操作。
- 保存成功/失败反馈。

不建议：

- 用 480px 小弹窗承载复杂设备配置。
- 每个 tab 使用完全不同的布局语言。
- 操作完成后没有状态反馈。

### 4.3 地图类

适用于：定位监控、历史回放、追踪、线路设置。

必须包含：

- 地图主画布。
- 左侧设备/客户树或筛选面板。
- 在线、离线、未激活等状态统计。
- 地图、卫星、围栏、更多、缩放等地图工具。
- 未选设备或加载失败状态。

不建议：

- 地图区域被侧栏或卡片压缩到不可用。
- 把地图页做成普通表格页。

### 4.4 视频类

适用于：实时视频、旅程影像、视频回放、事件中心、下载任务。

必须包含：

- 设备或客户选择。
- 视频通道或媒体结果区域。
- 设备在线/离线状态。
- 日期范围或回放条件。
- 空视频、无设备、无权限、加载失败状态。

不建议：

- 只做筛选表格，不体现视频通道/播放区域。
- 空视频状态写成泛泛的“暂无数据”。

### 4.5 报表类

适用于：运行统计、报警统计、温湿度统计、行业统计、区域统计、打卡统计、报表任务、数据导出。

必须包含：

- 日期范围。
- 客户/分组/设备筛选。
- 查询和重置。
- 统计图表或指标。
- 明细表格。
- 导出或任务状态。

不建议：

- 只做大数字卡片，不提供明细。
- 不说明最大查询时间范围。

## 5. 传感器类需求专项规范

传感器类需求是设备详情工作台里的硬件配置，不应被设计成独立的营销式页面或普通表单弹窗。

### 5.1 适用范围

包含但不限于：

- 载重设置。
- 油量设置。
- 门磁设置。
- 温湿度标签。
- I/O 设置。
- 蓝牙配件绑定。
- 报警阈值。
- 标定。
- 主设备蓝牙通信校验。

### 5.2 PM 必须补齐的业务信息

每个传感器需求必须写清楚：

- 支持哪些设备型号。
- 不支持的设备型号如何展示。
- 传感器是否需要开启开关。
- 支持有线、蓝牙，还是两者都支持。
- 有线和蓝牙下分别需要填写哪些字段。
- 是否需要主设备蓝牙先开启。
- 蓝牙开启失败怎么办。
- 配件是否支持从配件池选择。
- 是否支持手动录入。
- 配件是否允许重复绑定。
- 是否允许一个设备绑定多个同类配件。
- 保存后是否立即生效，还是需要等待设备应答。
- 设备离线时能否保存配置。

### 5.3 传感器页面推荐结构

顺序建议固定：

1. 当前设备上下文。
2. 说明提示：该传感器的安装前提和配置影响。
3. 启用/关闭开关。
4. 硬件配置：有线/蓝牙、配件、通信状态。
5. 参数配置：名称、类型、输入通道、标定值、单位。
6. 报警设置：开关、阈值、持续时间、通知方式。
7. 校验提示和错误状态。
8. 底部操作：取消、确定。

### 5.4 载重设置

PM 需要明确：

- 是否有载重监控开关。
- 数据传输：有线/蓝牙。
- 蓝牙配件是否 1:1 绑定。
- 标定需要几组数据。
- 模拟量单位。
- 载重单位。
- 空载/满载/实际载重的填写规则。
- 两组模拟量是否允许相同。
- 两组载重差值是否有建议或限制。
- 是否支持查看标定示意图。
- 空载报警、超载报警阈值。

原型必须体现：

- 关闭载重监控后的禁用状态。
- 获取模拟量按钮。
- 手动输入状态。
- 标定错误提示。
- 蓝牙配件配对成功、配对失败、低电量、未配对状态。

### 5.5 油量设置

PM 需要明确：

- 主油箱、副油箱是否都支持。
- 副油箱开启条件。
- 探测方式。
- 数据传输方式。
- 最大值、最小值、满箱油量、油箱形状、标准设定。
- 主/副油箱蓝牙配件如何绑定。
- 副油箱标定未完成时是否允许绑定。
- 偷油报警、低油报警阈值和单位。

原型必须体现：

- 主油箱和副油箱分组。
- 副油箱关闭时字段禁用。
- 标定未完成时的阻断提示。
- 蓝牙通信校验状态。

### 5.6 门磁设置

PM 需要明确：

- 支持几个门磁。
- 每个门磁是否可命名。
- 有线/蓝牙配置差异。
- 门磁通道或门位映射。
- 是否支持配件池选择。
- 是否支持解绑。
- 非法开门报警时间段。
- 开门超时报警阈值。

原型必须体现：

- 门磁列表。
- 已配对、未配对、配对失败状态。
- 单个门磁配置入口。
- 报警开关和阈值输入。

### 5.7 温湿度标签

PM 需要明确：

- 支持几个标签。
- 标签 ID、标签名称、蓝牙设备、电量、状态。
- 是否支持批量导入。
- 是否支持从配件池添加。
- 是否支持批量报警设置。
- 温度上限、温度下限、湿度上限、湿度下限、持续时长。
- 单个标签报警和批量报警的优先级。

原型必须体现：

- 标签表格。
- 批量操作。
- 单行配置。
- 已配对、配对中、未配对、低电量、绑定失败状态。
- 温度和湿度单位。

## 6. 需求评审时的检查清单

评审时按这个顺序检查：

1. 页面类型是否选对。
2. 是否保留设备/客户/服务核心字段。
3. 是否有完整默认流程。
4. 是否有新增、编辑、保存、取消、失败反馈。
5. 是否有加载、空、禁用、错误、无权限状态。
6. 是否有离线、未激活、过期设备处理。
7. 是否说明字段可编辑/只读/必填。
8. 是否说明表格列、操作列、分页、批量选择。
9. 是否使用现有组件和 token。
10. 是否出现禁止项。

只要前 6 项没补齐，就不要只讨论视觉细节。

## 8. 当前阶段建议

短期交付建议：

- 新需求统一使用本文件作为 PM 原型检查表。
- 涉及设备详情或传感器的需求，必须额外对照 `device-detail-workspace.md`。
- 涉及具体页面菜单的需求，必须额外对照 `route-inventory.md`。
- 涉及颜色、间距、字号、圆角的需求，必须额外对照 `design-tokens.md`。

中期深化建议：

- 先围绕“我的客户”和“设备详情工作台”补完整截图、弹窗、菜单和异常状态。
- 再整理成 Figma 组件和变量。
- 最后再补全报表、财务、组织、系统配置等低频页面的详细规范。
