## 1. 需求背景

当前 PC 端侧边导航层级较乱，中英文命名不够统一；用户反馈、搜索、消息和账号等入口分散在页面不同位置，整体 UI 风格也不一致。

本期对侧边导航、顶部导航、消息通知和轨迹回放四个模块进行分组、布局和视觉样式优化。

## 2. 本期范围说明

*   本文重点记录 Figma 相对现有系统发生变化的页面和区域。
    
*   改动区域的布局、组件样式、状态和文案以 Figma 为准。
    
*   Figma 未展示或未调整的页面、功能和交互全部沿用现有系统逻辑。
    
*   用户提供的轨迹回放截图为现有系统页面，仅作为改版前的对照基线。
    
*   本期侧边导航和顶部导航不调整现有权限、数据关系和接口逻辑。
    

## 3. 模块一：侧边导航

### 3.1 导航分组

侧边导航按照 Figma 重新分组和排序，明确一级菜单与二级菜单的层级关系。[请至钉钉文档查看附件《【产品】LBS功能菜单（SaaS国内海外）》。](https://alidocs.dingtalk.com/i/nodes/MNDoBb60VL9XQK0rHmkz5p2AJlemrZQ3?iframeQuery=anchorId%3DX02mshhnakjljdpn26scog)

| 区域 | 本次调整 |
| --- | --- |
| 一级菜单 | 账号首页、定位监控、视频监控、我的业务、司机管理、财务中心、开放平台、统计报表、应用市场、成员管理、系统管理等入口按 Figma 顺序展示 |
| 二级菜单 | “我的业务”下展示我的客户、设备记录、保养记录、分享管理；其他存在二级菜单的模块沿用原有内容，展示样式按 Figma 统一 |

### 3.2 样式调整

*   展开状态展示品牌标识、菜单图标、菜单名称及二级菜单层级。
    
*   收起状态仅保留品牌图标和一级菜单图标。
    
*   默认、悬停、选中、展开及二级选中状态按 Figma 展示。
    
*   统一导航背景、选中背景、图标、文字、间距和展开箭头样式。
    

### 3.3 保持不变

菜单对应的页面入口、权限和页面内部功能不变；Figma 未调整的子页面继续沿用现有系统。

## 4. 模块二：顶部导航

### 4.1 布局调整

将原本散落在不同区域的全局入口集中到顶部导航。

| 区域 | 本次调整 |
| --- | --- |
| 左侧 | 展示侧边导航开关和当前页面标题 |
| 用户反馈 | 统一放置于顶部操作区，并使用 Figma 中的入口样式和提示状态 |
| 搜索 | 调整搜索框、搜索范围切换及相关文字的布局和样式 |
| 语言 | 使用统一图标入口，弹出内容沿用现有语言切换逻辑 |
| 消息 | 使用统一消息图标和未读提示样式，点击后展示未读消息浮层 |
| 账号 | 展示头像、账号名称和下拉箭头；下拉菜单包含 Figma 中展示的产品入口、推送、密码和退出 |

### 4.2 状态与文案

*   顶部入口的默认、悬停、选中、展开和提示状态以 Figma 为准。
    
*   顶部导航中的图标、间距、背景、圆角及文案以 Figma 为准。
    

### 4.3 保持不变

各入口点击后的原有页面、搜索能力、语言切换和账号操作逻辑不变。

## 5. 模块三：消息通知

### 5.1 顶部未读消息浮层

*   点击顶部消息图标后，按 Figma 展示未读消息浮层。
    
*   浮层包含“未读消息”标题、“更多”入口及未读消息列表。
    
*   消息项展示标题、日期和摘要，数量、状态和文案以 Figma 为准。
    
*   点击“更多”进入消息中心，原有跳转逻辑不变。
    

### 5.2 消息中心

| 区域 | 本次调整 |
| --- | --- |
| 分类页签 | 展示报警信息、站内信息、系统公告、活动公告及对应未读数量样式 |
| 操作区 | 展示全部已读、标记已读和删除按钮，按钮样式及状态以 Figma 为准 |
| 筛选区 | 展示日期范围和设备名称搜索，布局和组件样式按 Figma 更新 |
| 消息列表 | 更新表头、勾选框、文字、已读/未读状态及行样式 |
| 分页区 | 更新总数、分页大小、页码和跳页区域的布局样式 |

补充规则：“全部已读”仅作用于当前分类，其他分类不受影响。

### 5.3 消息详情

*   报警消息详情页按 Figma 更新标题、来源、时间及报警信息区域的布局样式。
    
*   公告详情页按 Figma 更新标题、来源、时间和正文区域的布局样式。
    
*   返回、删除及地点等入口的图标、位置和文案以 Figma 为准。
    
*   消息规范文档：[请至钉钉文档查看附件《系统提醒文案 PC&#x2F;APP》。](https://alidocs.dingtalk.com/i/nodes/MNDoBb60VL9XQK0rHmkz5p2AJlemrZQ3?iframeQuery=anchorId%3DX02msikvd31i335jsiz4bo)
    

### 5.4 保持不变

消息读取、筛选、删除、详情查看、已读状态和分页等原有业务逻辑不变；Figma 未展示的其他消息页面继续沿用现有系统。

## 6. 模块四：轨迹回放

### 6.1 页面布局

*   轨迹回放页面接入新的侧边导航和顶部导航样式。
    
*   查询条件、地图区域、播放控制和底部数据区域按 Figma 重新排布并更新样式。
    
*   设备选择、日期、快捷日期、选项及播放入口的位置与状态以 Figma 为准。
    

### 6.2 本次明确调整

*   日期输入仅展示日期，不展示时分秒。
    
*   原播放区域中的“详情”和“速度”两个入口合并为“轨迹数据”。
    
*   点击“轨迹数据”后，继续打开原有底部数据面板，保留“详情、速度、行程、任务列表”四个页签。
    

### 6.3 保持不变

设备选择、轨迹查询、地图展示、播放控制及底部数据内容等原有逻辑不变；Figma 未调整的轨迹回放功能继续沿用现有系统。

## 7. 验收说明

*   四个模块中已调整区域的布局、样式、状态和文案与 Figma 一致。
    
*   侧边导航分组、顶部入口位置、消息页面和轨迹回放布局与目标稿一致。
    
*   Figma 未展示或未调整的页面与业务逻辑保持现状，不额外改动。
    
*   消息中心“全部已读”仅影响当前分类。
    
*   轨迹回放日期展示及“轨迹数据”入口符合本需求记录。
