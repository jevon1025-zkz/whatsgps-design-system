# 设备图标绘制、状态色转换与客户反馈复盘

本文沉淀设备图标绘制、状态色转换、地图小尺寸识别、客户反馈、交付检查和历史返工经验。目标是让后续图标在真实使用场景中同时满足设备类型识别和状态识别，并保持同一套视觉语言，避免重复出现“只改颜色却改坏材质”“大图能看但地图看不清”“图标能看但不能交付”等问题。

## 1. 适用范围

适用于 WhatsGPS / 立即定位 / Justrack 设备图标相关工作，包括：

- 默认设备图标绘制与优化
- 新增设备类型图标
- 车辆、工程车、宠物、人物、方向箭头等图标生成
- 静止、行驶、怠速/未定位、离线、断油电/超速等状态色转换
- 地图展示、设备详情、选择图标、图标库等场景下的图标验收

不适用于重新设计整套图标系统、重新定义状态含义、修改产品交互规则。

## 2. 核心原则

### 2.1 用户识别优先

图标第一优先级是让用户一眼识别设备类型。风格统一很重要，但不能压过识别性。

例：

- 出租车必须有清晰的 `TAXI` 或出租车特征。
- 警车必须保留警灯、警车文字或明确警车语义。
- 火车头不能画成子弹头或卡车。
- 小货车、大货车、挂车、牵引车、集装箱货柜必须在轮廓和结构上能分开。
- 农机、拖拉机、装载机、运输卡车必须有各自明确的机械特征。

### 2.2 轻 3D 质感优先

统一风格是轻 3D，不是照片级写实，也不是扁平插画。

应保留：

- 圆润体积
- 柔和高光
- 边缘阴影
- 局部凹凸细节
- 透明背景
- 512 x 512 PNG 源图

避免：

- 过度写实
- 扁平图标
- 果冻材质
- 塑料重绘感
- 高光生硬成白色贴片
- 重新生成导致材质体系变化

### 2.3 只换色，不换材质

状态色转换不是重新生成图片，而是基于正式母版进行颜色替换。

必须保留：

- 原始明暗结构
- 原始高光位置
- 原始阴影层次
- 原始边缘反光
- 原始透明通道
- 原始比例和构图
- 表情线、轮胎、玻璃、机械件等非目标区域

禁止：

- 重新画一张“看起来类似”的图
- 把轻 3D 改成塑料、果冻或扁平材质
- 用整图滤镜导致玻璃、表情、轮胎、底盘一起变色
- 只按色相换完就交付，不检查细节

## 3. 正式资产来源与发布门禁（3.0）

当前正式设备图标的唯一资产来源是设备详情 Figma 的 `图标替换/pc` 定稿区，Section 节点为 `48:8443`。已核验实例 `929:866` 的属性为 `离线状态 / 摩托车`，Figma 尺寸为 `42 x 42px`。

本机历史五状态目录、候选稿、过程检查图以及此前整理的 150 张 PNG 只用于追溯绘制过程和优化经验，不属于 3.0 正式交付资产。不得把这些文件缩放后作为 Figma 定稿，不得重新打包成“最终五状态图标库”。

完整正式图标包成立前，必须逐项从 Figma 最终实例导出，并建立清单，记录 Figma file key、Section/node ID、实例 node ID、状态、车型、Figma 尺寸、导出格式和导出时间。未完成逐节点导出与清单核验时，Skill 不捆绑或宣称拥有完整正式图标资产包。

## 4. 状态色规则

### 4.1 状态与颜色

| 状态 | 文件夹 | 颜色方向 | 备注 |
|---|---|---|---|
| 静止 | `设备图标 静止` | 蓝色 | 正式母版色，很多状态转换从这里开始 |
| 行驶 | `设备图标 行驶` | 绿色 | 以正式行驶文件夹效果为准，不要用荧光绿 |
| 怠速/未定位 | `设备图标 怠速:未定位` | 黄色 | 方向接近 `#FFB201` |
| 离线 | `设备图标 离线` | 灰色 | 方向接近 `#AAAAB1` |
| 断油电/超速 | `设备图标 断油电:超速` | 红色 | 方向接近 `#F21212` |

### 4.2 状态色转换方法

优先从正式母版转换：

1. 打开正式蓝色静止图。
2. 识别蓝色车漆、蓝色结构件、蓝色机身、蓝色服装等目标区域。
3. 只替换目标区域色相和饱和度。
4. 保留原始亮度曲线和材质层级。
5. 清理透明边缘或抗锯齿处的蓝色残留。
6. 输出到对应状态文件夹。
7. 生成五状态总览图做人工检查。

不要从错误预览图继续改。若某张预览图材质已经偏离正式体系，必须回到正式蓝色母版重新转换。

## 5. 图标绘制规则

### 5.1 车辆类

车辆类以顶视图为主。

要求：

- 车头朝上。
- 角度一致。
- 同车型保持车身比例一致。
- 车身不要被压扁或拉得过长。
- 轮胎外露程度要符合车辆类型，不要为了展示轮胎破坏透视。
- 顶视图不能出现正面玻璃逻辑。
- 同一套车图要有统一蓝色车漆、玻璃、轮胎和高光体系。

重点类型：

- 小轿车：修长、简洁、顶视图比例稳定。
- 警车：基于小轿车比例，增加警灯、警车识别信息，蓝白或红色状态转换都要保留白色车身中段和黑色玻璃。
- 出租车：必须保留出租车识别特征，如顶灯、`TAXI`、格子标识。
- 面包车：参考五菱宏光一类车身，避免和 SUV、微型车混淆。
- SUV / 越野车：可有备胎，但结构不要复杂到影响地图尺寸识别。
- 小货车：与大货车区分，封顶版本可以参考大货车结构但整体更短。
- 大货车：驾驶仓和货仓必须分明。
- 牵引车：只保留车头和鞍座结构，不要画成普通货车。
- 挂车：注意轮胎数量和透视，后轮不要过多，不必为了展示轮胎牺牲结构。
- 集装箱货柜：强调长方形箱体、箱门、筋条，保持顶视图。

### 5.2 工程车和农机

工程车和农机必须做到一眼识别。

要求：

- 装载机要有大轮胎、铲斗、臂架。
- 挖掘机要有机械臂和铲斗，但不要过度写实。
- 拖拉机要和农机区分，必要时增加顶棚、排气管等特征，但顶棚不能和座椅逻辑冲突。
- 农机如果复杂度过高，应简化到地图尺寸仍可识别。
- 运输卡车要参考真实运输卡车比例，不要画成正面车头。

### 5.3 非车辆类

包括电动车、自行车、滑板车、人物、宠物、牲畜、船、方向箭头等。

要求：

- 保持轻 3D 材质。
- 不强行改成顶视图，除非明确要求。
- 宠物类保留可爱、圆润、轻 3D 表情体系。
- 人物类只改服装状态色，保留皮肤、头发、白衬衫。
- 方向箭头只改箭头主体色，保留透明通道和高光阴影。

## 6. 宠物类专项规则

宠物类是最容易返工的一组，必须单独检查。

### 6.1 宠物爪印

问题高发点：

- 容易变成果冻材质。
- 底部阴影容易过饱和。
- 绿色版本容易出现透明胶感。

处理规则：

- 从正式母版转色。
- 保留圆润高光。
- 控制底部阴影，不要让深色边缘像透明胶。
- 不要整体提高饱和度。

### 6.2 猫咪

问题高发点：

- 头顶三条纹看不清。
- 脸颊纹和主体色阶太接近。
- 胡须和表情线容易被误染。

处理规则：

- 头顶三条必须在 512px 和实际地图尺寸都能读出来。
- 纹路比主体更深，但不能硬画成色块。
- 胡须、眼睛、嘴巴保持清晰。

### 6.3 狗狗

问题高发点：

- 斑块细节被吃掉。
- 耳朵阴影过重或过亮。
- 表情线糊成一团。

处理规则：

- 斑块要和主体有明显但柔和的层级。
- 鼻子、嘴巴、眼睛保持原始材质和清晰度。

### 6.4 牲畜

问题高发点：

- 鼻孔黑成一坨。
- 鼻子高光过亮。
- 耳朵和角的立体关系丢失。

处理规则：

- 鼻孔应保留立体边缘和内部暗部。
- 鼻子区域不能平刷。
- 耳朵内侧阴影要保留。

## 7. 人物类专项规则

人物状态色只改服装和领带。

必须保留：

- 皮肤
- 头发
- 白衬衫
- 领口阴影
- 脸部和身体比例
- 透明背景

不要把整个人物都套色。红色人物图标应从正式蓝色人物母版转换，不要使用历史预览或重新生成。

## 8. 方向框规则（3.0 最终定稿）

最终资产位于 `../direction-marker-no-shadow-handoff-20260706-173945.zip`。唯一有效规则如下：

- SVG、PNG 均使用 `64 x 64px` 透明画布。
- 可视方向框为 `42 x 54px`。
- 圆形底座圆心对齐画布中心 `(32,32)`。
- 围绕 `(32,32)` 原地旋转，不得偏移。
- 无阴影。
- 以设备详情 Figma 标注和包内最终交付资产为唯一实施依据。

## 9. 交付前检查清单

每次交付前必须执行以下检查。

### 9.1 文件检查

- 正式交付文件由 Figma 当前最终实例直接导出，不是历史 PNG 的缩放结果。
- 文件尺寸与对应 Figma 实例一致；`512 x 512` 仅是未来新增图标的工作源尺寸。
- PNG 保留透明通道；需要 SVG 时保留可验证的矢量结构。
- 文件名与图标库命名一致。
- 每个文件都有对应的 Figma 节点与导出信息清单。

### 9.2 视觉检查

- 和同状态、同家族图标材质一致。
- 和蓝/绿/黄/灰/红五状态并排看不突兀。
- 没有塑料、果冻、扁平化、照片写实偏差。
- 高光不是生硬白色块。
- 阴影没有被压黑或洗掉。
- 透明边缘没有蓝色残留。

### 9.3 识别检查

- 512px 大图能看清。
- 42px 左右实际地图尺寸仍可识别。
- 宠物表情、车辆类型、工程车结构没有丢。
- 状态色不会压过设备类型识别。

### 9.4 总览图检查

交付前必须生成 contact sheet，对比：

```text
蓝色静止 / 绿色行驶 / 黄色怠速:未定位 / 灰色离线 / 红色断油电:超速
```

不能只看单张大图通过就交付。

## 10. 常见错误和纠正方法

### 错误 1：把换色做成重新生成

表现：

- 材质变成粉色塑料。
- 宠物表情、边缘、高光都和正式图不一致。
- 车辆玻璃、轮胎、机械件也被误染。

纠正：

- 回到正式蓝色母版。
- 只改目标色区域。
- 保留原始亮度和阴影结构。

### 错误 2：只按用户指出的单点修

表现：

- 用户说猫纹看不清，就只加深猫纹。
- 用户说太暗，就整体提亮。
- 修完一个问题又产生另一个问题。

纠正：

- 先判断问题类型：颜色、材质、识别、路径、透明通道。
- 自己生成总览图先筛掉不能交付的版本。
- 不把半成品丢给用户做质检。

### 错误 3：绿色调试失控

表现：

- 绿色太亮，看不清细节。
- 降亮度后整体变灰变暗。
- 继续调整后材质变平或果冻。

纠正：

- 参考已通过的黄色版本。
- 保留原始明暗，不做全局压暗。
- 单独恢复纹路、斑块、鼻孔等细节层级。

### 错误 4：把本机文件夹当成正式资产来源

表现：

- 在桌面或历史状态文件夹里找到图，就误以为它仍是当前定稿。
- 预览图或独立 PNG 存在，但无法对应到当前 Figma 最终实例。
- 交付文件没有记录 Figma node ID、属性和实例尺寸。

纠正：

- 先确认 Figma 当前定稿 Section 和实例节点。
- 从当前最终实例直接导出，不能从本机历史目录补位。
- 交付时提供文件路径和 Figma 节点 manifest。

### 错误 5：预览图当正式图

表现：

- contact sheet 中看起来有红色宠物，但没有独立 PNG。
- 预览图材质已经不对，还继续沿用。

纠正：

- contact sheet 只用于检查。
- 正式交付必须有独立 PNG。
- 材质不一致时必须回到母版重做。

## 11. 推荐执行流程

### 11.1 新增图标

1. 明确实际使用场景和核心展示尺寸，地图图标默认按 `42px` 评估。
2. 明确设备类型、相近设备和必须保留的识别特征。
3. 找参考图，但不直接照抄；先说明准备强化哪些识别特征。
4. 确定视角、朝向、比例和状态色主要覆盖区域。
5. 先只制作蓝色静止母版，不提前批量生成其他状态。
6. 同时检查 `512px` 细节和 `42px` 地图轮廓。
7. 确认设备类型可识别、状态色面积足够、比例没有变形。
8. 静止母版确认通过后，才能批量转换其他状态色。
9. 检查透明背景；最终批准后更新 Figma 组件，由定稿实例导出发布资产。

### 11.2 状态色补齐

1. 找正式蓝色母版。
2. 确认目标状态文件夹。
3. 定义状态色区域和保护区域，确认状态色在 `42px` 下占比足够。
4. 只转换目标色区域，保持原始明暗、高光、阴影和透明通道。
5. 检查车身饰条、连接处、边缘反光等容易漏色的位置。
6. 清理残留蓝色像素，确认玻璃、轮胎和机械件没有误染。
7. 生成五状态对比总览和 `42px` 检查图。
8. 通过后更新 Figma 组件并保留历史版本。
9. 从最终实例导出独立资产，更新节点 manifest；不能只交付检查图。

### 11.3 返工处理

1. 不急着继续修图，先判断问题类型。
2. 若是材质不一致，直接回母版重做。
3. 若是细节不可读，优先拉开局部层级，不做全局滤镜。
4. 若是资产缺失，回到 Figma 最终实例确认，不从缓存或历史文件夹补位。
5. 返工后必须重新做总览检查。

## 12. 当前已确认的关键经验

- 红色宠物不能使用旧预览图，必须从正式蓝色宠物母版重新转换。
- 红色人物只改西装和领带，保留皮肤、头发、白衬衫。
- 绿色宠物不能只调亮暗，要单独处理猫纹、狗斑、牛鼻孔、爪印材质。
- 爪印绿色如果底部阴影过饱和，会变成果冻材质。
- 灰色状态容易把高光做硬，必须保持原蓝色母版的明暗曲线。
- 方向箭头状态色转换应保留箭头原始高光和边缘阴影。
- 车辆类顶视图必须车头朝上、角度统一。
- 图标验收不能只看 512px 大图，还要看地图实际尺寸和 Figma 状态矩阵。

## 13. 客户反馈与产品复盘

设备图标不是只要在 `512px` 下画得完整即可。客户最终接触的是地图上的小尺寸图标，因此必须同时解决两个问题：

1. 用户能否一眼认出设备类型。
2. 用户能否一眼判断设备当前状态。

以下两轮客户反馈都源于制作阶段只关注大图，没有充分验证实际地图尺寸。

### 13.1 第一轮反馈：货车和搅拌车状态色不明显

涉及图标：

- 小货车
- 大货车
- 搅拌车

#### 问题现象

- 原图只有车头使用蓝、绿、黄、灰、红状态色。
- 小货车和大货车后方车厢保留大面积灰色。
- 搅拌车后方搅拌罐保留大面积灰色。
- 在 `512px` 下能看到车头颜色，但缩小到地图尺寸后，车头只占很小面积。
- 用户主要看到的是灰色车厢或灰色搅拌罐，难以快速区分设备状态。

#### 根因

- 设计时把状态色当成局部车漆，而没有把它当成地图上的核心状态信息。
- 只检查了大图的造型和材质，没有检查 `42px` 下状态色的视觉占比。
- 没有评估车头、车厢和搅拌罐在缩小后的面积权重。

#### 修改方式

- 大货车：将后方车厢外壳纳入状态色，保留面板明暗和结构线。
- 小货车：将后方封闭车身外壳纳入状态色，避免只靠车头表达状态。
- 搅拌车：除车头外，后方搅拌罐主体也参与状态色表达。
- 保持玻璃、轮胎、黑色底盘、银灰机械件、车灯、尾灯、阴影、比例和顶视图不变。
- 扩大状态色覆盖时仍保留轻 3D 明暗，不能把车厢或搅拌罐处理成纯色平面。

#### 验收标准

- 在 `42px` 下不放大查看，也能快速区分五种状态。
- 状态识别不依赖车头的一小块颜色。
- 车厢和搅拌罐仍能看出结构、明暗和材质。
- 五状态并排时，颜色覆盖范围和结构位置完全一致。

#### 复盘结论

状态色必须覆盖设备在地图尺寸下的主要视觉面积。设计状态色区域时，应按缩小后的面积权重判断，不能按零部件语义机械地认为“只有车头属于车漆”。

### 13.2 第二轮反馈：摩托车在地图上过细

涉及图标：

- 摩托车

#### 问题现象

- 原摩托车顶视图车身过窄，纵向轮廓过强。
- 缩小到地图尺寸后接近一条竖线，油箱、车把和车身结构无法辨认。
- 用户难以一眼确认这是摩托车，也降低了地图上的可见性和可点击性。

#### 错误处理方式

- 直接把整张摩托车图标横向拉宽。
- 这种方式虽然增加了宽度，但会让轮胎、车身、仪表和机械结构一起变形。
- 变形后的图标不符合真实比例，也没有真正强化摩托车的识别特征。

#### 正确修改方式

- 保持轮胎、中轴、顶视图和车头朝上不变。
- 重新调整油箱和侧包围的可见面积，而不是缩放整张图片。
- 强化车把和后视镜形成的横向轮廓。
- 后视镜使用白灰材质，与蓝色车漆区分。
- 保持车灯朝向、仪表位置、座椅、排气和机械件符合顶视图结构。
- 先确认蓝色静止版，再从同一母版生成绿色、黄色、灰色和红色状态。

#### 本轮制作中暴露的执行问题

- 车灯位置和朝向一度不符合顶视图逻辑。
- 局部修补曾出现模糊、无意义色块和材质不一致。
- 后视镜一度错误使用蓝色车漆，应保持白灰色。
- 状态换色时，油箱盖外圈曾残留蓝色环境光。
- 仪表保护蒙版范围过大，误把仪表后方车身饰条锁住，导致其他状态残留蓝条。
- 交付时曾只展示检查图，没有直接提供四张正式状态图片。

#### 验收标准

- 在 `42px` 下能看出油箱、车把、后视镜和前后轮廓，不再像一条线。
- 不能通过整体拉伸制造宽度，车轮和车身比例必须自然。
- `512px` 下没有模糊块、错误灯位、蓝色后视镜或残留蓝色车漆。
- 五状态的结构、比例、透明通道和明暗关系完全一致。
- 每个制作状态都有独立的 `512 x 512 RGBA PNG` 工作源；正式发布尺寸以 Figma 最终实例为准。

#### 复盘结论

地图图标的轮廓识别优先于大图中的写实细节。遇到小尺寸不可见问题时，应重新设计关键轮廓和面积关系，不能用整体拉伸或局部堆细节解决。

### 13.3 两轮反馈的共同结论

- `512px` 是制作源图，`42px` 才是核心验收场景。
- 设备类型识别和设备状态识别是两个独立指标，必须分别检查。
- 大图中清楚的局部颜色或结构，缩小后可能完全消失。
- 静止母版未通过地图尺寸检查前，禁止批量生成其他状态。
- 客户不应承担基础质量检查，交付前必须自行发现比例、漏色、误染和小尺寸不可读问题。

## 14. 设备图标设计前置门槛

以下问题必须在开始绘制前回答。任何一项不明确，都不能直接生成图标。

### 14.1 使用场景

- 图标最终出现在哪个页面或地图场景？
- 实际显示尺寸是多少？
- 是否需要支持点击、聚合、重叠或深浅地图背景？

默认要求：至少检查 `512px` 源图和 `42px` 地图图标。

### 14.2 设备类型识别

- 用户凭什么一眼认出这个设备？
- 哪三个结构是缩小后仍必须保留的识别特征？
- 它最容易与哪些已有设备混淆？
- 轮廓上准备如何与相近设备区分？

不能只依赖小文字、细线或缩小后会消失的零件。

### 14.3 状态识别

- 状态色覆盖了多少主要视觉面积？
- 缩小后是否还需要仔细寻找车头颜色？
- 大面积灰色或白色结构是否会压过状态色？
- 哪些主体结构可以合理纳入状态色？

状态色必须成为第一眼可见的信息，但不能误染玻璃、轮胎和机械件。

### 14.4 视角和比例

- 是否使用统一顶视图？
- 车头是否朝上？
- 同类车型角度和车身比例是否一致？
- 轮胎、车灯、驾驶舱和货箱是否符合真实透视？

不能用整体拉伸、压扁或错误正面结构解决识别问题。

### 14.5 材质和细节

- 是否符合现有轻 3D 图标家族？
- 高光、阴影和边缘反光是否柔和？
- 哪些细节在 `42px` 下仍有意义？
- 是否存在为了展示绘制能力而增加、但会干扰识别的结构？

无助于小尺寸识别的复杂细节应简化。

### 14.6 换色范围

- 哪些区域属于车漆或状态色结构？
- 哪些区域必须锁定不变？
- 连接处、饰条、挡泥板、边缘反光是否会漏色？
- 保护蒙版是否误盖了应该换色的车身区域？

换色前应明确列出“修改范围”和“保持不变范围”，不能边生成边猜。

## 15. 强制阶段验收

### 阶段 1：需求和参考确认

输出：设备用途、相近设备、关键识别特征、视角、状态色覆盖方案。

未完成以上内容，不开始绘制。

### 阶段 2：蓝色静止母版

输出：一张 `512 x 512 RGBA PNG` 蓝色静止版。

只检查造型、比例、识别特征、轻 3D 材质和透明背景，不提前制作其他状态。

### 阶段 3：真实尺寸验证

输出：`42px` 实际图和放大检查图。

必须确认：

- 设备类型能一眼识别。
- 轮廓不是一条线或模糊色块。
- 状态色预留面积足够。
- 与相近设备放在一起仍能区分。

### 阶段 4：状态色扩展

静止母版确认后，才生成绿色、黄色、灰色和红色状态。

要求：

- 同一结构、同一比例、同一透明通道。
- 只改变状态色区域。
- 五状态明暗关系和材质一致。

### 阶段 5：交付前自检

必须完成：

- 五状态 `512px` 总览。
- 五状态 `42px` 总览。
- 关键连接处和换色边缘放大检查。
- 残留蓝色、误染、模糊、材质变化检查。
- 工作源尺寸、RGBA、透明通道检查，以及 Figma 最终实例与 manifest 对应检查。

未通过自检的图片不能交付给用户继续挑错。

### 阶段 6：Figma 定稿与发布导出

1. 将批准母版与状态变体更新到 Figma 对应组件并保留历史版本。
2. 核验最终实例的状态、车型、尺寸和展示规则。
3. 从 Figma 最终实例直接导出独立资产，不使用本机历史 PNG 替换。
4. 在 manifest 中记录 node ID、属性、尺寸、格式、文件和导出时间。
5. 记录本轮问题、原因和处理结果，补充到本文档。
